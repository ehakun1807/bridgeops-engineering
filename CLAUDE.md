# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

- `npm run dev` — Vite dev server on **port 3000** (not the default 5173). Configured in `vite.config.ts`.
- `npm run build` — production build to `dist/`.
- `npm run preview` — serve the built `dist/` locally (port 4173).
- `npm run lint` — `tsc --noEmit` (TypeScript type-check; no ESLint).
- `npm test` — Jest. Test files live in `__tests__/` and match `**/__tests__/**/*.test.ts`.
- Run a single test: `npx jest __tests__/<file>.test.ts` or `npx jest -t "<test name>"`.
- `npm run deploy:rules` / `deploy:indexes` / `deploy:firestore` — Firebase deploys.

`GEMINI_API_KEY` must be set in `.env.local` for local dev and in Vercel's project env vars for prod. The key is **server-only** — read by the `api/*.ts` handlers via `process.env.GEMINI_API_KEY`. It is NOT injected into the client bundle (the old `define` block was removed — see 2026-05-13 session log). Never reintroduce it into `vite.config.ts`'s `define` or any client-side code.

## Architecture

**Flat layout — no `src/` directory.** Every component, client, and helper sits at the project root. The path alias `@/*` resolves to the project root (both Vite and tsconfig). Imports must include explicit `.tsx` / `.ts` extensions (`allowImportingTsExtensions: true`).

**Entry & routing.** `index.tsx` mounts `App.tsx`. `App.tsx` implements hash-based routing via `VIEW_TO_PATH` / `PATH_TO_VIEW` maps and the `View` union type in `types.ts`. Heavy views (`Dashboard`, `RampScoreTool`) are `React.lazy`-loaded to keep the marketing-home bundle lean. Adding a new view means: extend the `View` union in `types.ts`, register it in both maps + `VIEW_TITLES` in `App.tsx`, and add the lazy import.

**Two surfaces in one app.**
1. *Marketing site* (Hero, Services, Pricing, MethodologyLayers, ContactForm, etc.) — public.
2. *Admin / SaaS dashboard* (Dashboard → ProjectDeepDive → AdvancedToolsModal → BOMAnalyzerTool [user-facing label "Alt BOM"] / QuoteCompareTool / DocGuardTool [user-facing label "Doc Guard"], plus RampScoreTool, ScoreHistoryPanel, GateDeliverablesModal, TaktStudyTool, etc.) — gated by Firebase auth.

**ProjectDeepDive tab strip (2-tier).** Primary row = General Info + 4 score buckets (full card chrome, live %). Secondary strip below = AI Analysis / Studies / History (lightweight pills, separate `layoutId="deepdive-utility-underline"` so the active highlight doesn't morph between rows). Adding a new utility tab = append to the `utilityTabs` array around `ProjectDeepDive.tsx:1465`; no JSX duplication needed.

**Auth & admin gating.** `firebase.ts` initializes the Firebase app from `firebase-applet-config.json` and exports `auth` + `db` (Firestore). `config.ts` defines `ADMIN_EMAIL` and `isAdminUser()` — this is a UX gate only; the real security boundary is `firestore.rules` (`isAdmin()`). Keep `ADMIN_EMAIL` in `config.ts` and the rules file in sync.

**AI integrations.** `aiClient.ts`, `coachClient.ts`, and `docGuardClient.ts` are the front-end clients. The `api/` folder (`ai-analyze.ts`, `ai-coach.ts`, `find-equivalent.ts`, `docguard.ts`, `docguard-upload-token.ts`) holds serverless handlers that wrap Gemini. All five enforce the same admin gate: Firebase ID-token signature verify against Google's RS256 public keys, reject anything not matching `ADMIN_EMAIL` with `email_verified==true`. The two `docguard*` handlers also use Vercel Blob for client→server PDF transfer (see gotcha below).

**Domain logic / generators.** `rampGroups.ts`, `productSegments.ts`, `productStandards.ts`, `templates.ts`, `indicators.ts`, `pptxGenerator.ts` (PPTX export via `pptxgenjs`), `taktMath.ts` (pure IE math — takt, mean, stdDev, CV, normalized/standard time, bottleneck, line balance loss, capacity verdict, validation gates), `taktXlsx.ts` (xlsx workbook builder for time-study export, uses SheetJS), `utils/docGuardPdf.ts` (annotated-PDF builder via `pdf-lib` — extends each annotated page with a right-side findings sidebar, appends a verdict-coded summary page), `utils/docGuardPdfHelpers.ts` (pure helpers — `wrapText`, `groupByPage`, `sortFindingsForSummary` — no `pdf-lib` import so they're directly testable), and `notify.ts` are pure-ish modules consumed by the dashboard tools.

**Firestore collections.** `users`, `projects`, `scores`, `tasks`, `leads`, **`taktStudies`** (one doc per time-study; `userId + projectId` scoped), **`docGuardAudits`** (one doc per PDF audit run; `userId`-scoped, project-agnostic for v1, optional `projectId` field reserved). When a takt study is marked completed, `TaktStudyTool` mirrors a snapshot to `projects/{id}.taktSummary` (`{ studyId, studyName, taktSec, bottleneckSec, balanceLoss, capacity, completedAtMs }`) so the project header pill + future RampScore consumers can read the verdict without scanning the whole collection. Drafts never write the mirror; Reopen / Delete leave it alone (point-in-time snapshot). `docGuardAudits` are immutable historical records (`allow update: if false`) — re-running an audit creates a new doc; the corresponding composite index `(userId asc, createdAtMs desc)` is declared in `firestore.indexes.json`.

**Testing.** `jest.config.*` uses `ts-jest` + `jsdom`. Note `testMatch` is `*.test.ts` only — `.tsx` test files will be ignored. Setup file: `jest.setup.js`.

## Repository gotchas

- **`.claude/worktrees/<branch>/` contains full duplicates** of source files (it's a git worktree for a feature branch). **Never edit files there** — Vite doesn't import from it, but it shows up in `Grep` results and is misleading. Always edit at the project root.
- **`dist/` may exist locally** even though it's `.gitignore`d. If you see a stale build, the dev server on port 3000 is the source of truth — anything else (preview, deployed site) needs `npm run build` first.
- **Hash routing only.** Don't introduce `react-router-dom` or path-based routing without updating the routing logic in `App.tsx`.
- **No ESLint.** "Lint" means `tsc --noEmit`. Type errors are the lint signal.
- **Vite stale-cache symptom**: if a code edit isn't visible in the browser even after reload, kill the dev server and run `rm -rf node_modules/.vite dist` before restarting `npm run dev`. Vite's transform cache occasionally serves old compiled output.
- **Port drift**: `npm run dev` will silently fall back to 3001/3002/etc. if 3000 is occupied by a previous orphaned process. Check the terminal's `Local: http://localhost:XXXX` line and kill stragglers with `lsof -ti:3000 | xargs kill -9`.
- **Multi-database Firestore deploys lie.** `firebase.json` uses the array form for `firestore` because the project runs on a named database (`ai-studio-c787093b-8e5e-45dc-8458-6bfe3ae5539d`, not `(default)`). `npm run deploy:rules` will print **`✔ Deploy complete!`** even when nothing was actually written to the named database — verify via Firebase Console → Firestore → Security; if the "Last published" timestamp didn't change, the deploy lied. **Reliable workaround:** open the local `firestore.rules`, copy all, paste into the Console rules editor (Cmd+A → Delete → Cmd+V to avoid appending to the existing rules), click Publish. CLI flags worth trying first: `npx firebase deploy --only firestore --force --project gen-lang-client-0703668573`.
- **`.firebaserc` is required.** Without it, every Firebase CLI command errors with "No currently active project." File maps `default` → `gen-lang-client-0703668573`. Should be checked in.
- **Vercel function body limit is 4.5MB.** Any endpoint that takes a file in a JSON body via base64 will 413 once the file passes ~3MB raw (base64 inflates by ~33%, plus JSON envelope). `/api/docguard` was originally written this way and broke on an 8MB upload. Fix: `/api/docguard-upload-token` issues a Vercel Blob client upload token, the browser uploads directly to Blob (no function in the middle, no body limit), then the client sends only the Blob URL to `/api/docguard`. The handler fetches the URL server-side, encodes to base64, calls Gemini, and `del()`s the blob in a `finally` block. Auth flows via `clientPayload` because `@vercel/blob/client.upload()` doesn't forward arbitrary headers — `onBeforeGenerateToken` reads it back and runs the Firebase admin verify. The Blob store must be **public** access (the audit handler fetches via plain `fetch()` with no signed creds); URLs are deliberately short-lived (60s token validity) and deleted post-audit. **Required env var: `BLOB_READ_WRITE_TOKEN`** — auto-injected when a Blob store is linked to the Vercel project; nothing manual to set.
- **`.claude/worktrees/<branch>/` shows up as a phantom submodule.** The worktree path got registered in the parent repo's git index as a gitlink (the format submodules use), but there's no `.gitmodules` file. GitHub Desktop displays "Submodule changes" warnings even though it's not a real submodule. Fix once: `git rm --cached .claude/worktrees/<branch>` then `echo ".claude/worktrees/" >> .gitignore`. Never re-add the worktree to tracking. Independent issue from the Jest/grep duplicate-file gotcha already documented above — both have the same root (worktree at the project root) but different fixes.
